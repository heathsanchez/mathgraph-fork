# TRISKELION CHECKPOINT 2 — QuixBugs scale protocol

Protocol ID: `TRISKELION_QUIXBUGS_SCALE_V1`. This document and its code, corpus hashes, task order, labels, routing rules, prompts, model settings, verifier, arms, and gates are frozen before any scale-model call.

## Frozen substrate

- Base model: `Qwen/Qwen3.5-9B` through River.
- Temperature: `0.0`; output maximum: `1400`; seed base: `20260818`.
- Source: `jkoppel/QuixBugs` at commit `4257f44b0ff1181dedaedee6a447e133219fcebf`.
- Qualification audit: all 40 Python tasks have a passing reference; 37 buggy programs fail and 3 time out in isolated tests. Audit 001 is retained as an infrastructure negative; audit 002 is the qualifying evidence.
- Acquisition set: `knapsack`, `gcd`, `lis`, `breadth_first_search`, and `powerset`.
- Protected set: all remaining 35 Python tasks, split before calls into five seven-task categories recorded in `CORPUS_MANIFEST.json`.
- The model sees the buggy module and the contract docstring. It never sees protected tests or reference implementations.

## Five frozen arms

1. `COLD`: no cross-task state.
2. `RAW_MEMORY`: the five unscoped acquisition episodes, including failed and repaired source.
3. `ALWAYS_ON`: all five retained capability manifests and callable critic outputs.
4. `VERIFIED`: only capabilities selected by the frozen source-and-contract router.
5. `WRONG_SCOPE_MANIFEST`: the identical capability registry and critic artifacts, with the VERIFIED activation count preserved but deliberately redirected to capabilities outside the human-frozen applicability labels where possible.

The wrong-scope arm changes applicability metadata/routing, not the available artifacts. Manifest wording is generated by the same callable and is approximately length matched at each task by preserving activation count.

## Capability interpretation

Checkpoint 1 separately established one direct executable AST-transform closure. The Checkpoint 2 artifacts are deterministic executable prompt critics (`render_guidance`-equivalent callable representations). This experiment tests whether explicit scoped guidance transfers on natural package tasks; it must not be described as direct source rewriting.

The human applicability matrix was assigned from buggy/reference diffs before River calls and is used only for measurement and construction of the deliberately wrong intervention. VERIFIED routing cannot access it. Router inputs are only buggy source and public contract.

## Output normalization and verifier

The candidate is the last fenced block that parses as a complete Python module. Failure to produce one is a model-output failure. Each candidate is executed against the untouched upstream test file in a fresh copied snapshot, with `python -B`, `PYTHONDONTWRITEBYTECODE=1`, a 15-second limit, and cache purge. A passing candidate is immediately replayed in a second fresh copy. The original file is restored in `finally`, provenance hashes are recorded, and isolation makes semantic verdicts independent of candidate order.

Infrastructure failures are counted separately and do not become scientific failures. Every prompt, response, response hash, normalized candidate, verifier output, latency, output-token count, selection, false activation, and missed activation is retained as raw evidence.

## Frozen metrics and gates

Primary quantities are task success, false and missed activation, output errors, latency, tokens, and 95% Wilson intervals. Differences use the predeclared conservative Newcombe construction from Wilson intervals:

- `Δsuccess = p(VERIFIED) - p(COLD)`;
- `ΔFA = pFA(ALWAYS_ON) - pFA(VERIFIED)`.

Primary gates:

- all 175 arm-task observations complete;
- zero infrastructure errors;
- VERIFIED success exceeds COLD;
- VERIFIED success exceeds ALWAYS_ON;
- VERIFIED false activation is lower than ALWAYS_ON;
- WRONG_SCOPE_MANIFEST success is lower than VERIFIED.

The point-estimate gates are reported even when their 95% intervals include zero. Confidence bounds, failures, and negative outcomes remain visible. River seed equality is not assumed: identical seeds only freeze the requested setting. This source-distinct scale test uses independent tasks as replications; causal installation tests continue to freeze the actual proposal hash before runtime intervention.

## Claim boundary

A positive result supports bounded transfer and scope control for this fixed model, corpus, registry, and router. It does not prove broad model improvement, universal repair laws, deterministic sampling, or direct executable repair on every task. Failure is retained as scientific evidence unless caused by infrastructure.
