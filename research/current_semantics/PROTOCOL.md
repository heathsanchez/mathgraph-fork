## Repairs and native gates

Only projects with independently confirmed discrepancies receive repair calls.
Both model and investigator are forbidden from seeing reported issue fixes before
the first generated repair freezes. At most two calls per project; each edits the
original source afresh using <=4 production files, <=6 disjoint literal edits per
file and <=200 changed lines total. Tests and expected answers cannot change.
All native generated-code execution occurs in token-free, nonroot, read-only,
network-disabled resource-limited Docker containers. API steps execute only fixed
harness code. No upstream message/PR, deployment or production mutation.

Each candidate must correct all frozen discrepancies, preserve every correct
audit observation, and preserve the complete original project test roster and
all original passes/skips. Baseline full project tests must qualify first; errors,
timeouts, missing submodules or missing test identities are UNKNOWN. Preserve both
failed candidates and unsuccessful infrastructure work. Native pytest follows
JSON Patch's declared tests/property_tests collection and fastjsonschema's
declared non-benchmark suite. External current official cases remain separate
from the upstream pinned test-suite submodule.

After initial discovery, search current issues/PRs to classify prior reports and
recheck live source heads. This can qualify known/open current defects; it does
not guarantee previously unreported novelty. Never resample targets to obtain a
winner. Fresh source observations are a new qualification boundary, not inherited
from cached old receipts.
